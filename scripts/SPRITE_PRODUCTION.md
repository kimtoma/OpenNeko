# Importing generated production sprites

The Swift/AppKit importer stages artwork generated by `image_gen`, preserves
source provenance, and checks source pixels, output geometry, and runtime metadata.
The native-cat workflow uses **one independently generated native image for every
frame**, then writes **1024×1024 RGBA** sprites for a **128-point** runtime canvas.
Creative changes, missing anatomy, and recolors belong in `image_gen`.
`highres1024` describes the output resolution; pixel-style artwork uses this mode
without passing through the older 64-pixel logical canvas. The selected
[round-cat source set](../assets/gen/pixel-housecats-1024-20260906/README.md) has
284 native 1254×1254 generation originals. Current export and release evidence is
linked from the [production report](../docs/SPRITES-PIXEL-1024-2026-09-06.md).

| Mode | Output canvas | Bottom padding | Art span / jump span | Grounded bottom |
| --- | ---: | ---: | ---: | ---: |
| `highres1024` | 1024 | 96 | 832 / 800 | 928 |
| `highres` | 256 | 24 | 208 / 200 | 232 |
| `pixel64` | 128 | 12 | 104 / 100 | 116 |

All modes display at 128 points. Both high-resolution modes use premultiplied
bilinear sampling and retain soft alpha. The explicit `pixel64` compatibility
mode renders a 64-pixel logical image and doubles it into a binary-alpha 2×2 grid.
The original directory-based command still defaults to `highres`; a source
manifest defaults to `highres1024`.

## Native source manifest

A version-1 manifest accepts four independent frame files or one four-cell sheet
for each state. Paths are relative to the manifest, or may be absolute. Each
`skin/state` pair must be unique. Separate frame files remain in their declared
order and must use four distinct paths.

```json
{
  "version": 1,
  "mode": "highres1024",
  "scalePolicy": "require-native-fit",
  "background": "chroma-magenta-pixel",
  "entries": [
    {
      "skin": "default",
      "state": "idle",
      "frames": ["default/idle_0.png", "default/idle_1.png", "default/idle_2.png", "default/idle_3.png"]
    },
    {
      "skin": "effects",
      "state": "nyang_punch",
      "frames": ["effects/nyang_punch_0.png", "effects/nyang_punch_1.png", "effects/nyang_punch_2.png", "effects/nyang_punch_3.png"]
    }
  ]
}
```

The selected production input is the measured
[character-size manifest](../output/character-scale-revision-20260906/sources.json):
70 character state groups plus one effect group, referencing **284 independent
native frames**. Its per-entry `artLimit` values carry the approved size plan; the
minimal example above only illustrates the file layout. The schema also
supports 2×2 or 1×4 sheets for other art sources. A 1254-pixel 2×2 sheet does not
provide 1024 pixels per pose and is unsuitable as the native production source.

Each entry can override `scalePolicy`, `background`, `artLimit`,
`preserveAltitude`, and `keepMainBody`. Background selection resolves in the order
entry override, explicit CLI `--background`, manifest root, then `auto`.
Root-level `neutralFloor` and `neutralSpread` configure neutral-background cleanup.
Native-frame entries retain
all meaningful detached features by default; do not enable `keepMainBody` merely
to hide a source defect, since whiskers and props can be separate components.

`highres1024` defaults to `no-upscale`: the shared state scale cannot exceed 1.0.
If native artwork is too small to fill the intended art span, it keeps its real
size and the report increments `nativeFitLimitedFrames`. The stricter
`require-native-fit` policy rejects that shortfall. `fit` allows enlargement only
when explicitly selected; reports always expose the actual ratio and upscale
count. Enlarging old 256-pixel sprites is not the native-cat workflow.

## Character-size normalization

The selected revision targets 400 output pixels of cheek breadth, about 50 points
on the 128-point runtime canvas. The
[selected measurements](../output/character-scale-revision-20260906/measurements-selected.json)
exclude ears, detached whiskers, limbs, torso, tail and props. Side profiles use
the visible forehead-to-muzzle breadth. The 280 character frames use 70 fixed
coat/state factors. The full-body punch follows the same group policy.

Most groups use a representative measurement. `default/jump`, `black/jump`,
`orange/jump`, and `pink/jump` use their four-phase median; the punch also uses a
four-phase median. One factor applies to every phase in the group. Manual
measurements have approximately 2–3% uncertainty, and a turned or airborne face
can have a different projected width without a change in source scale.

The [plan generator](../output/character-scale-revision-20260906/prepare-scale-manifest.py)
converts the reviewed reference widths into per-entry `artLimit` values, retaining
the importer's bilinear support reservation. It rejects a target that would
enlarge a measured group. The manifest's `characterScale` block records the
measurement reference and hash; `artLimit` is the field that drives import.
The [scale plan](../output/character-scale-revision-20260906/scale-plan.json) and
[scale audit](../output/character-scale-revision-20260906/scale-audit.json) retain
actual factors and output agreement. Do not normalize by whole-silhouette height:
keyboards, tails and extended limbs are part of the drawing, not face-size cues.

After the measurements have been reviewed, regenerate the complete plan:

```bash
python3 output/character-scale-revision-20260906/prepare-scale-manifest.py \
  output/character-scale-revision-20260906/measurements-selected.json \
  --target 400 --include-effects
```

This writes the revision's `sources.json` and `scale-plan.json`. Changing a
measurement or entry limit changes the manifest hash. Reimport every group after
such a change; an append into an older manifest index must fail rather than mix
scales from two plans. The selected revision completed all 284 exports and final
effect checks; the
[release artifact record](../dist/character-scale-20260906/artifact.json) records
the verified package and exact resource agreement.

## Commands

Run from the repository root on macOS. Pass an absolute source-manifest path so
its relative frame references resolve consistently:

```bash
swiftc -O -module-cache-path /tmp/openneko-sprite-module-cache \
  scripts/sprite-production.swift -o /tmp/openneko-sprite-production

/tmp/openneko-sprite-production self-test

# Import an approved four-frame group while other images are still being made.
/tmp/openneko-sprite-production import-manifest \
  --source-manifest "$PWD/output/character-scale-revision-20260906/sources.json" \
  --only default/idle \
  --output-dir output/sprite-pixel-1024-20260906/default-idle-review

# Progressively add or replace completed groups in the final staging directory.
/tmp/openneko-sprite-production import-manifest \
  --source-manifest "$PWD/output/character-scale-revision-20260906/sources.json" \
  --only default/idle,calico/idle --append true \
  --output-dir output/sprite-pixel-1024-20260906

# Complete staging, metadata, audit and review boards after all sources exist.
bash scripts/import-generated-sprites.sh \
  output/character-scale-revision-20260906/sources.json \
  output/sprite-pixel-1024-20260906 highres1024 \
  --background chroma-magenta-pixel --punch-facing right

# Inspect a source's native size, alpha bounds and canvas-edge contacts.
/tmp/openneko-sprite-production source-info --mode highres1024 --background chroma-magenta-pixel \
  --sheet assets/gen/pixel-housecats-1024-20260906/default/idle_1.png \
  --report output/sprite-pixel-1024-20260906/source-info.json

# A single-frame review keeps its intended frame number.
/tmp/openneko-sprite-production import --mode highres1024 --background chroma-magenta-pixel \
  --sheet assets/gen/pixel-housecats-1024-20260906/default/idle_1.png \
  --states idle --rows 1 --columns 1 --frame-start 1 \
  --output-dir output/sprite-pixel-1024-20260906/single-frame-review/default \
  --report output/sprite-pixel-1024-20260906/single-frame-review/import.json

# Verify installed PNGs against their original source and import evidence.
/tmp/openneko-sprite-production audit --mode highres1024 \
  --sprites App/Resources/sprites \
  --source-reports output/sprite-pixel-1024-20260906 \
  --report output/character-scale-revision-20260906/installed-bundle-audit.json
```

`--only` accepts comma-separated `skin/state` keys. By itself it writes an index
for just those groups. `--append true` preserves previously staged groups and
replaces matching entries, provided the source manifest and mode are unchanged.
Incomplete indexes cannot pass a complete bundle audit. The batch
wrapper requires all five skins and all four effect frames. It stages files and
review material; installing art remains a separate step after visual approval.

## Alpha isolation and source edges

- Any source with native nonopaque alpha keeps that alpha, including fine fur,
  whiskers, and soft boundaries. Detached eight-connected components whose
  maximum alpha is below 16 are removed as trace noise. An alpha-1 pixel connected
  to visible artwork is preserved. Explicit `chroma-magenta` instead passes native
  alpha through unchanged, including all connected and detached nonzero-alpha
  pixels; it only zeros hidden RGB where alpha is already zero.
- Fully opaque sources first use a conservative exterior flood with minimum RGB
  channel 220 and maximum channel spread 18. The batch then removes neutral
  fringe within at most two source pixels of the known exterior, using minimum
  channel 160 and spread 36. Bright pixels retained by the conservative mask are
  protected. An unrestricted lower-threshold flood can enter a weak outline gap
  and erase white fur; a regression fixture reproduces and prevents that failure.
- A source with a meaningful isolated canvas-edge contact is rejected, because
  adding output padding cannot restore clipped ears, tails, or paws. For the 1024
  profile, edge contacts consisting only of alpha below 16 are retained and
  padded. Reports distinguish all edge contacts from alpha ≥16 contacts, before
  and after isolation, so faint connected traces do not imply missing anatomy.
- Sheet cells use the nearest fully transparent gutter. Missing gutters fail
  instead of cutting through a feature. Independent full-frame images do not
  require artificial sheet assembly or equal source dimensions.
- RGB is zero under fully transparent output pixels. Sampling first premultiplies
  color by alpha, preventing hidden background colors from creating halos. No
  binary alpha threshold or 64-pixel intermediate is used in high-resolution modes.

## Explicit magenta sources

Use `--background chroma-magenta` or the manifest's `"background":"chroma-magenta"`
only for artwork generated against a reserved saturated-magenta matte. `auto`
never selects this mode. The selected round pixel set uses
`chroma-magenta-pixel` instead. For other sources reviewed under strict
`chroma-magenta`, the wrapper accepts the same explicit override:

```bash
bash scripts/import-generated-sprites.sh \
  path/to/strict-magenta-sources.json \
  output/strict-magenta-review highres1024 \
  --background chroma-magenta
```

The key is removed globally, including an enclosed gap between a tail and body.
Native nonopaque-alpha sources take precedence and pass through without keying.
Opaque sources with no reserved key are rejected. White coat, green eyes, peach
cheeks, pink ears, and intact outline pixels are not globally desaturated.

Generated matte color is not always exactly `#FF00FF`. The importer measures the
actual key and records its tolerance. A near-key outlier can be removed only when
every adjacent source pixel is strict key; this handles isolated canvas-corner
matte noise without treating a real clipped feature as padding.

Dark spill must connect to actual key through a magenta-colored path and stay
within twelve source pixels. The extension beyond four pixels excludes light
lavender/checker patches. Nearby existing matte and dark outline colors constrain
the coverage estimate; original observed RGB is unmixed into physical foreground
RGB and soft alpha. The importer never copies a neighboring texture into the
artwork. A generated edge with clipped color channels may require a physical RGB
projection. Green-floor and upper-gamut projections are counted separately and
must recompose within eight byte levels of the observed RGB. Unsupported colors
and over-deep or disconnected candidate patches remain
unchanged and make source/import QA fail. This is a source defect to review, not
an invitation to widen the mask or repaint the coat.

`chromaMagenta` evidence includes removed key and enclosed-hole counts, isolated
key outliers, decontaminated edge pixels, gamut projections, low-coverage matte traces, unresolved
counts grouped by reason, compositing error, native-alpha passthrough, and source
and isolated RGBA hashes. Source PNG bytes remain unchanged. An import may write
staged PNGs and review boards before returning a QA failure; a staged file's
presence does not imply that the source passed.

### Reserved-color pixel fringe

`--background chroma-magenta-pixel` is a separate, explicit choice for pixel
characters whose generation prompt reserves magenta exclusively for background.
It keeps native-alpha precedence above. Reserved-magenta mixtures are keyed to
transparent only within sixteen source pixels (Chebyshev distance) of a measured
key pixel. This spatial distance is distinct from color-connected path depth.
The pixel policy reconstructs no foreground RGB: this avoids colored glints from
generated edge colors that do not obey linear compositing. Nonmagenta foreground
is untouched, and premultiplied-alpha resampling supplies clean output coverage.

The report records `fringePolicy`, `reservedFringePixelsRemoved`, and
`maximumReservedFringeDistance`. Only high-saturation reserved magenta is keyed
globally (`min(R,B)>=160`, `min(R,B)-G>=96`, `abs(R-B)<=96`), allowing the actual
generated background to vary in shade. Lower-chroma interior colors are left
byte-identical and counted as `interiorHueCandidatesPreserved`; a hue match alone
must not remove dark ink, a cheek or a nose inside the cat. Neutral bright pixels
(`min(R,G,B)>=220`, channel spread at most18) are explicitly protected. Trimming
more than five percent of nonkey pixels (with a 64-pixel noise allowance) fails
instead of silently changing a character's shape. The selected 1024px pixel-cat
manifest uses this policy; strict `chroma-magenta` retains its original behavior.
Review the result at native resolution and against light and dark backgrounds.

## Geometry and runtime metadata

A state uses one scale for its four frames. Every source retains its measured
native canvas and content bounds. When separate native canvases have different
heights, their coordinate systems align by bottom-edge translation; pixels are
not resized to manufacture equal source dimensions. The vertical offset and
actual source-to-output ratio appear in every frame record.

Grounded states share the mode's bottom boundary using the complete visible alpha
region. A keyboard, bowl, laptop, or other prop may extend below the paws and
therefore determine that boundary; the importer does not identify anatomical
feet. Jump and dragging preserve relative source altitude unless
`preserveAltitude` overrides that behavior. The default jump art limit reserves
headroom for runtime lift; a measured entry's `artLimit` takes precedence. A
one-pixel bilinear footprint is included in scale selection, and the actual
soft-alpha bottom is aligned by whole-pixel translation.

For 1024-pixel sprites, `render-info.json` records `canvasHeight:1024`,
`bottomInset:96`, `displayHeight:128`, and `filtering:"linear"`. The importer
measures `dragTopInset` from all four dragging frames. Effects use the same canvas,
display height, and bottom inset without a dragging inset. Runtime texture loading
must retain the 1024-pixel backing image while honoring the 128-point display size.
The five coat directories and effect directory produce six metadata files. For
metadata-enabled dragging, the runtime caches the visible alpha outline when a
texture is decoded and minimally translates the rotated result into the canvas.
Transparent canvas padding does not drive this correction; the hot drag path
does not rescan pixels or read textures from disk.

Effects also need an explicit artwork direction when they differ from the legacy
left-facing sequence. Pass `--punch-facing right` to `effect-metadata` or the
import shell wrapper for the selected round pixel set. This writes
`punchFacing:"right"` only in the effect metadata. Omission preserves legacy
left-facing playback. The runtime flips the effect toward the target and ignores
global effect metadata when it falls back to skin frames. Validate both target
directions against the source drawing; dimensions and transparent borders alone
cannot establish the correct direction.

Source pose and anatomy differences remain visible. Shared scaling cannot make
independently drawn faces identical. The audit reports bounds, centroid variation,
area variation, duplicate frames, and cross-skin alpha differences for review.

## Evidence and validation

Every manifest group writes a report under `reports/`, a contact sheet under
`contact-sheets/`, and an entry in `source-import-index.json`. The report identifies
every original file and SHA-256, native dimensions, source bounds, edge contacts,
alpha cleanup, source scale, fit shortfalls, output bounds, and exact RGBA hash.
The index records the source manifest's hash. Original sources stay unchanged.
Each source's pixels and hash come from the same immutable file read, so another
worker replacing a generated file cannot mix old pixels with a new source hash.

The bundle audit checks the actual runtime manifest, PNG dimensions/format,
padding, transparent RGB, frame counts, effects, and source protection. With
`--source-reports`, it requires all relevant reports, zero protected-white loss,
matching original file hashes, and exact output RGBA hashes. Changed or missing
native source files, stale output evidence, or a changed source manifest fail.
The report includes verified source/output counts and source-scale ranges.

The original 21-report sheet layout remains supported. If no source reports are
available and none are required, the audit explicitly reports source protection
as `unavailable`; structural validity then makes no source-preservation claim.
Soft alpha is valid in both high-resolution modes. Only `pixel64` requires binary
alpha and a 2×2 lattice. Effects remain separate from the 280 character frames;
use `--effects false` only for an explicit character-only check.

Regression checks cover weak-gap white-fur preservation, native soft alpha,
premultiplied edge colors, existing 128/256 output behavior, 1024 geometry,
unequal native canvases, common state scale, no upscaling, mixed source layouts,
source/output provenance, metadata, and jump headroom. They also cover explicit
magenta extraction, enclosed holes, exact coat/ear/cheek/eye/outline preservation,
known matte mixtures, ambiguous-color rejection, and native-alpha passthrough.
Contact sheets and light/dark/blue boards at 128 and 256 pixels check facial detail,
silhouette, state meaning, and animation continuity. Chroma-isolated sources also
need native-size edge review: use `background-preview --sizes 512,1024` so a fine
colored rim cannot hide in a reduced preview.
