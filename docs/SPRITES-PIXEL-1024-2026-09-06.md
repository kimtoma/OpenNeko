# Round pixel house cats — motion and character-size revision

OpenNeko's selected **style 1** uses a round face, compact body, and fine pixel
details in five ordinary house-cat coats: white, black, orange, calico, and cream.
The compatible internal ID `pink` displays the cream coat.

The source inventory contains **284 native 1254×1254 generation originals**:
five coats × 14 states × four frames, plus four full-body punch frames. Production
exports are **1024×1024 RGBA PNGs** displayed on a **128-point** runtime canvas.
The [source audit](../output/character-scale-revision-20260906/source-originals-audit.json)
verifies original bytes, dimensions, prompts, and current provenance.

## Completed character changes

All five coats received four new frames for each of these five motions, replacing
100 originals:

| Motion | Accepted behavior |
| --- | --- |
| `walk` | Four-legged gait with two distinct hind paws and alternating support. |
| `typing` | Alternating forepaws visibly press a physical keyboard; its case, key rows, and spacebar remain stable. |
| `dragging` | Left/right wriggling with visible palm pads and toe beans. |
| `error` | Friendly dizzy confusion after reasoning fails. |
| `coding` | A seated cat watches AI coding progress on a laptop, with both forepaws resting away from the keys. |

The subsequent size review replaced one more original,
[`black/hover_2.png`](../output/character-scale-revision-20260906/black-hover-source-change.json),
to correct an undersized intermediate head. The current source audit distinguishes
this one change from the completed 100-frame motion revision. Each selected PNG
still matches its native generated original; approved replacements retain their
own prompts, references, hashes, and backup evidence.

## Consistent size between motions

The 280 character frames use one uniform reduction per coat/state, fixed across
that state's four frames. The reference is **400 output pixels of cheek breadth**,
or about **50 points** at the 128-point display size. Ears, detached whiskers,
paws, torso, tail, and props are excluded from the cheek measurement. Side views
use the visible forehead-to-muzzle breadth.

The [selected measurements](../output/character-scale-revision-20260906/measurements-selected.json)
record manual uncertainty and pose differences. Most groups use a representative
measurement; the `default`, `black`, `orange`, and `pink` jump groups use the
four-phase median to balance crouched and airborne projections. The full-body
punch uses the same measurement policy with a four-phase median. A single group
factor preserves natural perspective and motion; frames are never independently
resized to force every projected face to the same width.

Normalization is complete for **all 284 frames in 71 groups**, including the four
punch phases. The cat, limbs, tail, and props keep their original proportions.

The [scale plan](../output/character-scale-revision-20260906/scale-plan.json) and
[source manifest](../output/character-scale-revision-20260906/sources.json) carry
the selected limits. The importer reads per-entry `artLimit` values and keeps one
source-to-output scale across each four-frame group. It uses `highres1024` with
`require-native-fit`, with no source enlargement or low-resolution intermediate.
Actual ratios and output agreement are recorded in the
[scale audit](../output/character-scale-revision-20260906/scale-audit.json).

## Alpha and runtime geometry

The explicit `chroma-magenta-pixel` policy removes the reserved generated matte
and bounded edge spill while protecting neutral bright fur. Native source alpha
takes precedence. The importer does not reconstruct foreground RGB; it downsamples
premultiplied color and zeros RGB in fully transparent output pixels. Native
generation files remain unchanged by normalization.

Six `render-info.json` files describe the five coats and the separate effect:
1024-pixel canvases, 128-point display height, 96-pixel bottom inset, and linear
filtering. Coat metadata also records a dragging top inset. SpriteKit retains the
1024-pixel backing textures.

Bottom alignment uses the lowest nontransparent exported content, including a
keyboard, bowl, or other prop when it extends below the paws. It is an alpha-bound
alignment, not anatomical paw detection. Dragging preserves its source motion;
the runtime caches the visible alpha outline and minimally translates a rotated
sprite inside the canvas. Empty transparent corners do not determine the clamp.

The full-body punch source faces right. Its effect metadata declares
`punchFacing:"right"`, and runtime playback faces the selected target. Effects
without that field retain the legacy direction convention. See the
[import workflow](../scripts/SPRITE_PRODUCTION.md) for policy and metadata details.
